# AGENTS.md

Static site generator repo. `node tools/build.mjs` renders `index.html` from
`data/courses.json` + `src/template.html`; output is committed and served as-is.

## Commands

| Task | Command |
|---|---|
| Build site | `node tools/build.mjs` |
| Optimize card art | `node tools/optimize-images.mjs` |
| Local preview | open `index.html` (no dev server, no deps, no package.json) |

There is no lint/typecheck/test tooling. Verification is: run the build, read the
generated `index.html` diff, and check the rendered page at each `.lgrid`
breakpoint (3 / 2 / 1 columns), in dark mode, and in print preview.

## Conventions

- Zero runtime dependencies. No npm packages, no framework.
- Plain CSS with custom properties in `assets/css/tokens.css`; component styles
  in `assets/css/main.css`, ordered as they appear in `src/template.html`.
- Flat BEM-ish class names with the `l*` prefix (`lcard`, `lbody`, `labtn`,
  `lres`). Never inline `style` attributes.
- Both light and dark tokens must exist for any new colour variable.
- Every interactive element needs a `:focus-visible` outline.
- Icons are `<i class="bi-…" aria-hidden="true">` from the `icons.css` subset;
  external targets use `target="_blank" rel="noopener noreferrer"`.
- Keep `data-track` / `data-search` attributes on `.course-card` intact — the
  filter and search in `assets/js/main.js` depend on them.

## Workflow

Work in **phases**. Each phase is a self-contained unit of change that leaves the
site in a working state.

1. Break the request into phases, then track each phase as TO-DO items with the
   TODO tool. Exactly one item is `in_progress` at a time; mark items completed
   only after the change is verified, not when it is merely written.
2. Make **atomic, logical commits** within a phase — one concern per commit, no
   unrelated changes bundled in. Short single-line messages in conventional
   commit style, matching the existing history:
   - `feat:` new behaviour · `fix:` bug fixes · `perf:` performance
   - `refactor:` no behaviour change · `chore:` tooling/config
   - Scopes used in this repo: `build`, `tools`, `links`, `cards`, `a11y`
3. **Push at the end of each phase**, before starting the next one.
4. Do not wait for a phase to finish to push when the change needs to be tested
   through CI, a deployed preview, or another external check — push early and
   keep going.
5. Never commit anything other than the source files and the regenerated build
   output they belong to; `index.html`, `robots.txt` and `sitemap.xml` are
   generated by the build script.
